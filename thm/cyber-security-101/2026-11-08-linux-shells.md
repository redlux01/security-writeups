## TL;DR

Понятие командной оболочки (Shell) как связующего звена между пользователем и ядром ОС, интерактивное взаимодействие с терминалом, обзор различных типов шеллов (Bash, Zsh), основы написания и запуска shell-скриптов, а также практический разбор логики скриптов авторизации (The Locker Script).

Базовые навыки работы с командной строкой Linux: навигация по каталогам (`pwd`, `cd`, `ls`), просмотр файлов (`cat`) и фильтрация текста через поиск (`grep`).

## Ход решения

### 1. Введение в командные оболочки (Introduction to Linux Shells)

* **Shell (Оболочка):** интерпретатор командной строки, выступающий в роли посредника между пользователем и ядром операционной системы (Kernel). Он принимает текстовые команды и преобразует их в системные вызовы.

### 2. Взаимодействие с оболочкой (How To Interact With a Shell)

* Работа в терминале начинается с приглашения ввода (Shell Prompt).
* **Bash (Bourne Again Shell)** — стандартная оболочка по умолчанию для большинства дистрибутивов Linux.
* Основные интерактивные команды для первичной разведки и навигации:
  * `pwd` — отображение текущего рабочего каталога.
  * `cd` — смена директории.
  * `ls` — вывод содержимого папки.
  * `cat` — чтение содержимого файлов.
  * `grep` — поиск заданных шаблонов или ключевых слов в тексте.

### 3. Типы командных оболочек (Types of Linux Shells)

* В системе может быть установлено несколько интерпретаторов. Список доступных зарегистрированных оболочек хранится в файле `/etc/shells`.
* Текущий активный шелл можно узнать с помощью команды `echo $SHELL`.
* Различные оболочки (например, `bash`, `zsh`, `sh`, `dash`) предлагают разный функционал, поддержку подсветки синтаксиса, автодополнения и особенности обработки переменных.
* Команда `history` позволяет выводить список всех ранее выполненных команд в текущей сессии.

### 4. Основы написания скриптов (Shell Scripting and Components)

Скрипты расширения `.sh` автоматизируют последовательности команд и включают стандартные программные конструкции:

* **Shebang (`#!`):** обязательная первая строка скрипта (например, `#!/bin/bash`), определяющая, какой интерпретатор должен исполнять код файла.
* **Права на выполнение:** перед запуском скрипта ему необходимо присвоить исполняемые права с помощью команды `chmod +x script.sh`.
* **Управляющие конструкции:** использование переменных, условных операторов (`if/else`) и циклов (`for`, `while`) для автоматизации рутинных и итеративных задач.
* **Комментарии:** строки, начинающиеся с `#`, которые игнорируются интерпретатором при выполнении.

### 5. Разбор скрипта (The Locker Script)

Анализировал пользовательский скрипт авторизации:

* Изучил исходный код скрипта для поиска логических уязвимостей, данных или условий ввода.
* Исправил все ошибки, что были.
* Запустил скрипт в контролируемой среде и проверил результат его выполнения с правами привилегированного пользователя (`sudo su`).

### 6. Практические упражнения (Practical Exercise)

* Применение утилит поиска (`find`, `grep`) для извлечения скрытых флагов и конфигурационных файлов.
* Анализ системных журналов в каталоге `/var/log/` для поиска следов входа в систему и анализа безопасности.

## Где я застрял

* Попытка запустить `.sh` скрипт напрямую без добавления прав на выполнение (`chmod +x`), что приводило к ошибке отказа в доступе.
* Важность указания правильного пути в shebang (`#!/bin/bash`), чтобы сценарий не пытался выполниться в старом `sh` с другим синтаксисом.

## Что понял

* Shell — это мощный инструмент не только для ручного ввода команд, но и для написания мини-автоматизаций (скриптов), ускоряющих администрирование и аудит.
* Понимание типов шеллов помогает ориентироваться в кастомизированных окружениях (например, при переходе с Bash на Zsh).
* Анализ чужих скриптов (The Locker Script) отлично тренирует навыки чтения кода и поиска логических ошибок.
