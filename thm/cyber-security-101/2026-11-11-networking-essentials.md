## Ход решения

### 1. Анатомия IPv4-адреса и маски подсети (IP Addresses & Subnet Masks)

IPv4-адрес состоит из 32 бит, разделенных на 4 октета (по 8 бит). Адрес делится на две части: **Network ID** (идентификатор сети) и **Host ID** (идентификатор конкретного узла).

* **Subnet Mask (Маска подсети):** определяет, какая часть IP-адреса относится к сети, а какая — к хосту (например, `255.255.255.0`).

* **CIDR-нотация (Classless Inter-Domain Routing):** компактная запись маски подсети с помощью слэша и количества сетевых бит (например, `/24` эквивалентно `255.255.255.0`).

* **Network Address & Broadcast Address:** 
  * Первый адрес подсети (все биты хоста = 0) — адрес самой сети.
  * Последний адрес подсети (все биты хоста = 1) — широковещательный адрес (Broadcast).

### 2. Публичные и приватные IP-адреса (Public vs Private IP)

Для предотвращения быстрого истощения IPv4-адресов адресация была разделена на два типа:

* **Private IP (Приватные адреса):** используются внутри локальных сетей (LAN) и не маршрутизируются в глобальном Интернете (стандарт RFC 1918):
  * `10.0.0.0` – `10.255.255.255` (`10.0.0.0/8`)
  * `172.16.0.0` – `172.31.255.255` (`172.16.0.0/12`)
  * `192.168.0.0` – `192.168.255.255` (`192.168.0.0/16`)

* **Public IP (Публичные адреса):** уникальные во всём мире адреса, назначаемые провайдерами (ISP) для выхода в глобальную сеть.

### 3. Механизм NAT (Network Address Translation)

**NAT** позволяет множеству устройств из локальной сети с приватными IP-адресами выходить в Интернет, используя один внешний публичный IP-адрес маршрутизатора.

* Маршрутизатор подменяет внутренний IP и порт отправителя на свой внешний IP и временный порт, фиксируя соответствие в таблице трансляции (NAT Table).

### 4. Динамическая настройка сети (DHCP)

**DHCP (Dynamic Host Configuration Protocol)** — протокол автоматического назначения IP-адресов, масок подсети, шлюзов по умолчанию и DNS-серверов подключаемым устройствам.

* Процесс получения адреса работает по схеме **DORA**:
  1. **Discover:** клиент отправляет широковещательный запрос на поиск DHCP-сервера.
  2. **Offer:** сервер предлагает клиенту свободный IP-адрес.
  3. **Request:** клиент запрашивает предложенный IP-адрес.
  4. **Acknowledge:** сервер подтверждает аренду (Lease) адреса.

### 5. Система доменных имён (DNS)

**DNS (Domain Name System)** — «телефонная книга» Интернета, преобразующая человекопонятные доменные имена (например, `tryhackme.com`) в IP-адреса.

* Иерархия DNS: Root Servers (`.`) $\rightarrow$ TLD Servers (`.com`) $\rightarrow$ Authoritative Name Servers (`tryhackme.com`).

* Основные типы DNS-записей:
  * **A:** сопоставляет имя с IPv4-адресом.
  * **AAAA:** сопоставляет имя с IPv6-адресом.
  * **CNAME:** каноническое имя (псевдоним для другого домена).
  * **MX:** указывает на почтовый сервер домена.
  * **TXT:** текстовые записи (часто для верификации и защитных механизмов SPF/DKIM).

## Где я застрял

* Расчет доступных хостов в подсети: нужно всегда помнить о вычитании 2 адресов (адрес сети и broadcast-адрес) из общей формулы $2^{(32 - CIDR)} - 2$.

* Отличие рекурсивных DNS-запросов от итеративных: рекурсивный запрос обязывает DNS-сервер самому найти конечный IP, а итеративный возвращает клиентскому резолверу адрес следующего DNS-сервера в цепочке.

## Что понял

* NAT и приватные диапазоны RFC 1918 — главные причины, почему IPv4 до сих пор активно используется, несмотря на исчерпание адресов.

* DHCP-процесс (DORA) целиком завязан на широковещательных (Broadcast) запросах на физическом/канальном уровне, так как у клиента в момент старта ещё нет своего IP.

* Понимание записей DNS критически важно для разведки (Reconnaissance) в кибербезопасности.
